# LiveTSM выбираем режим загрузки

Редакция r08 · 13.10.2026.

## Linux или Windows выбирает пользователь

**Клиент:** У нас на компьютере установлены Linux и Windows. С LiveTSM пользователь сможет сам выбирать систему? Каждый раз нужно вызывать администратора безопасности?

**Ответ продавца:** Да, режим совместимости позволяет сохранить выбор операционной системы через разрешённый загрузчик, например GRUB. Администратор один раз настраивает LiveTSM для передачи управления GRUB и задаёт разрешённую конфигурацию. После проверок LiveTSM пользователь самостоятельно выбирает Linux или Windows в меню GRUB. Перенастраивать LiveTSM для каждого переключения не требуется.

**Польза пользователю:** работать в нужной операционной системе без обращения к администратору при каждом выборе.

**Польза администратору:** меньше повседневных обращений из-за переключения ОС. Однократная настройка относится к выбору между уже разрешёнными системами; обновления и изменение разрешённой конфигурации обслуживаются по регламенту.

### Два режима под разные задачи

| Вопрос | Прямая загрузка Linux | Режим совместимости через GRUB |
|---|---|---|
| Что запускает LiveTSM | Непосредственно ядро Linux | Разрешённый EFI-загрузчик GRUB |
| Основная цепочка | LiveTSM → ядро Linux | LiveTSM → GRUB → Linux либо Windows Boot Manager → Windows |
| Что происходит с shim и GRUB | Оба исключены из этой цепочки | GRUB остаётся в цепочке; необходимость других компонентов зависит от конфигурации |
| Кто выбирает систему | Администратор задаёт разрешённый путь запуска | Пользователь выбирает систему из разрешённого меню |
| Главное преимущество | Сокращение цепочки и числа доверенных компонентов | Гибкость пользователя и отсутствие перенастройки LiveTSM при каждом выборе ОС |
| Компромисс безопасности | Применим для прямого запуска Linux | Цепочка длиннее; дополнительные компоненты и пути увеличивают поверхность атаки. Администратор осознанно принимает снижение безопасности относительно сокращённого варианта |

Для Windows сохраняется штатная цепочка через Windows Boot Manager. Прямая загрузка ядра относится к Linux; Windows не описываем как прямой запуск ядра средствами LiveTSM.

Две установленные системы — **dual boot**; несколько — **multiboot**. Это выбор одной ОС при включении, а не одновременная работа нескольких ОС. Допустимые системы определяет администратор. EFI-приложение другого загрузчика может использоваться в режиме совместимости при подтверждённой совместимости его конкретной конфигурации.

### Что продавец показывает на демонстрации

1. Администратор настраивает передачу управления разрешённому GRUB и согласует доступные ОС.
2. При включении LiveTSM выполняет настроенные проверки и при успешном результате передаёт управление GRUB.
3. Пользователь выбирает Linux и запускает её; после перезапуска выбирает Windows.
4. Переключение между разрешёнными ОС не требует изменения настроек LiveTSM администратором.

**Фраза для клиента:** LiveTSM позволяет выбрать сокращённую цепочку загрузки Linux или сохранить привычное меню выбора ОС — под задачу вашего рабочего места.

### Уточнения для технического специалиста

Передача управления GRUB не означает, что сам факт его запуска гарантирует контроль всех последующих компонентов. Состав контролируемых объектов — образ загрузчика, конфигурация, модули, компоненты ОС и параметры — фиксируется по выбранной политике и версии. Единственный разрешённый старт через LiveTSM должен сохраняться и в режиме совместимости. Конкретный механизм допуска последующих EFI-образов при Secure Boot Custom описывается инженерной конфигурацией; произвольное расширение разрешений прошивки не объявляется защитой от обхода.

### Термины сценария

- ОС — операционная система.
- EFI — Extensible Firmware Interface, интерфейс прошивки; UEFI — Unified Extensible Firmware Interface, его унифицированная спецификация.
- GRUB — GRand Unified Bootloader, загрузчик с меню выбора ОС.
- shim — промежуточный EFI-загрузчик, применяемый в некоторых схемах Secure Boot Linux.
- Windows Boot Manager — штатный диспетчер загрузки Windows; далее запускает загрузчик Windows.
- dual boot — выбор между двумя ОС; multiboot — выбор между несколькими ОС.
- МДЗ — модуль доверенной загрузки.

1. Уточнения руководителя продукта LiveTSM в текущем обсуждении от 13.10.2026: прямая загрузка ядра Linux исключает shim и GRUB; режим совместимости сохраняет выбор ОС без перенастройки LiveTSM при каждом переключении. Это источник сведений о реализации продукта.
2. [GNU GRUB Manual](https://www.gnu.org/software/grub/manual/grub/grub.html) — выбор ОС и chain-loading; [Secure Boot и shim](https://www.gnu.org/software/grub/manual/grub/html_node/UEFI-secure-boot-and-shim.html).
3. [Linux EFI Boot Stub](https://cdn.kernel.org/doc/html/latest/admin-guide/efi-stub.html) — возможность загрузки ядра без отдельного традиционного EFI-загрузчика; не описание внутренней реализации LiveTSM.
4. [Microsoft BCD для UEFI](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/bcd-system-store-settings-for-uefi) — Windows Boot Manager и Windows loader.
5. [UEFI PI LoadImage](https://uefi.org/specs/PI/1.9/V2_Services_Boot_Services.html) — применение политики безопасности при загрузке EFI-образов.
